# Distroforge

Distroforge sets up an Ubuntu 24.04 LTS Distrobox for everyday use or software development on a Linux host. Both profiles include systemd inside the container, tools for working with `.deb` packages, desktop libraries, and Zsh with Oh My Zsh. You can also enable a user systemd service to start the container when you log in.

## Requirements

- A Linux host with Bash. Automatic startup at login requires an active systemd user session.
- Distrobox and either rootless Podman or local Docker accessible to your user. If both engines are available, the installer prefers an existing Distrobox with the requested name. For a new container, it prefers Podman.
- `sudo` if the installer needs to install system packages. It can do so on hosts with APT, DNF, Pacman, or Zypper.
- Network access to pull the Ubuntu image, install Ubuntu packages, and clone Oh My Zsh. The development profile also downloads asdf and supports `amd64` and `arm64`.

## Install

From the project directory, run the installer as your regular user:

```sh
./install.sh
```

In a terminal, the installer prompts for any missing options. The defaults are the `common` profile, the name `Ubuntu` (`UbuntuDev` for `development`), a shared home, and automatic startup at login. Pass the four options to run without prompts:

```sh
./install.sh --profile common --name Ubuntu --home shared --autostart yes
./install.sh --profile development --name UbuntuWork --home separate --autostart no
```

| Profile | Installed tools |
| --- | --- |
| `common` | Desktop and `.deb` support, command-line utilities, and Oh My Zsh. |
| `development` | Everything in `common`, plus a C/C++ toolchain, CMake, pkg-config, ripgrep, Python with pip and venv, libraries for building Python versions, and asdf 0.20.2. |

Both profiles use `ubuntu.ini`. The installer adds `ubuntu-development.ini` to the base manifest for development. Inside the development Zsh session, asdf stores plugins, runtimes, and shims under `~/.config/distrobox/zsh/<name>/asdf`. Install the plugins and language versions you need from inside the container.

| Home mode | Behavior |
| --- | --- |
| `shared` | The container uses your host home directory. If Distrobox has a custom home configured, clear its `container_user_custom_home` or `container_home_prefix` setting as applicable, or select `separate`. The installer checks for this conflict before creating a container. |
| `separate` | The container stores its home under `${XDG_DATA_HOME:-$HOME/.local/share}/distrobox/homes/<name>` and links available host folders such as Documents and Downloads. Host files remain accessible through Distrobox's mounts. |

Rerun the same command to configure an existing container and repair folder mappings in an unmodified `user-dirs.dirs` generated by an earlier installer. Choose a different name to use a different profile or home mode.

Names must be 2 to 128 characters, start with a letter or digit, and contain only ASCII letters, digits, dots, hyphens, or underscores. For names that would produce an overly long hostname on older Distrobox releases, the installer uses the host's hostname unless you set `DBX_CONTAINER_HOSTNAME`.

## Enter the container

Use the command printed by the installer. For the default container with Podman, run:

```sh
DBX_CONTAINER_MANAGER=podman distrobox enter Ubuntu
```

Use `docker` if the installer selected Docker, and substitute your name if you created a named container.

## Run host tools

Both profiles expose `podman` and `docker` from inside the container when the corresponding commands are available on the host. The shortcuts use `distrobox-host-exec` and the host session bus. Commands run with your host account and use the host's engine and permissions. The helper may offer to install `host-spawn` on first use. Use `distrobox-host-exec <command>` to run other host programs.

## Manage startup at login

Use `--autostart no` to start the container manually by entering it. Rerunning the installer with this option also disables a login service it previously configured for that container. With `--autostart yes`, the `Ubuntu` container uses `distrobox-ubuntu.service`. Other names use `distrobox-ubuntu-<name>.service`. The service waits for a login even on systems with user lingering enabled.

```sh
systemctl --user status distrobox-ubuntu.service
journalctl --user -u distrobox-ubuntu.service -b
systemctl --user disable --now distrobox-ubuntu.service
```
